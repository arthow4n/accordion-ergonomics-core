# Early provisional target catalog

Publish the catalog before unresolved skin/envelope calibration or new search
infrastructure can delay exercise delivery. [Definitions](../../targets/definitions.json)
are musical targets and physical contact strategies; the generated
[manifest](../../targets/manifest.json) and [catalog](../../targets/CATALOG.md)
are derived from exact 037 frozen evidence. Ten deliberately varied targets
include five contact controls, two sampled relocations, one sampled held task,
a return-sequence hypothesis and two physical realizations of musical C4.
The return and second C4 button are explicitly hypotheses at this release.

Target IDs are curated musical identities. Physical realization IDs hash the
named finite contact events, independently of candidate ordering. Branch IDs
hash compiled-world identity, joint names and saved qpos. Multiple branches
belong to one physical realization, not separate exercises. Musical pitches are
recomputed from the finite canonical mapping; alternative buttons must preserve
all event pitches. Search definitions and actual candidate result files are
hashed links, including failed starts in discovery evidence. No old rectangular
or v2 state is promoted to the current world.

The reference has two registered compiled variants: index-only and index/middle
contact-site composition. Instrument/player/setup/contact-profile hashes must
match; each result retains its exact compiled hash. This distinction is explicit,
not an assertion that all contact-site compositions compile identically. Solver
iteration budgets are search evidence, separate from physical world identity.

All entries retain null human feasibility and unresolved anatomical validation.
037 independent coverage applies to endpoints, not all movement samples; a
numerical path is not complete anatomical validity. No difficulty score, tempo,
force, physiological effort, instrument motion or extra supported finger is
introduced. Collision auditing proceeds in the separate 038 investigation.

Rebuild with `uv run aec targets build`; inspect via `list`, `show TARGET_ID`, and
`verify TARGET_ID`. The verify command checks file commitments, frozen roots,
current catalog derivation, exact registered worlds, button mapping and endpoint
requirements. It explicitly leaves scientific validity and human feasibility
unknown. Focused schema, deterministic derivation, identity, unsupported-contact
and evidence-tampering tests accompany this release.
